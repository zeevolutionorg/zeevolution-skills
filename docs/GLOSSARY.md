## 🧰 The repository

| Term | Meaning |
|---|---|
| **Technologist** | Anyone doing technical work: engineers, data scientists, designers, product managers. |
| **Category** | A folder of skills for one aspect of a technologist's work (e.g. `career-management`). |
| **Toolkit skill** | The user-invoked entry skill of a category (`*-toolkit`) that sets up its documents. |
| **Foundations** | Shared skills every category uses: setup, cloud-workspace, doc-templates, disciplines. |

## 👥 People and modes

| Term | Meaning |
|---|---|
| **Self mode** | Building a hub for your own career. |
| **Lead mode** | Building a hub for someone you lead. |
| **Person** | Who the documents are about. |
| **Leader** | The person's manager — in self mode, the user's manager or mentor. |

## 🗓️ Rituals

| Term | Meaning |
|---|---|
| **Bi-weekly 1:1** | The recommended 1:1 every two weeks, where the Hub is walked and documents are updated. |
| **Working Agreement** | Five questions at the first 1:1 about how the person likes to work, be followed up and get feedback. |
| **Career Check** | Seven questions about direction, once a quarter (the first bi-weekly of the quarter). |

## 📄 Documents

| Term | Meaning |
|---|---|
| **Career Hub** | The central document: links every other document and sets the bi-weekly rhythm. |
| **Development plan** | Either the **Growth Plan** or the **Focus Plan** — alternatives; the pair chooses one. |
| **Growth Plan (PDI)** | Plan built from the gap to the next level: self-analysis + three moves. |
| **Focus Plan** | Plan built from the work ahead: time split, goals, what success looks like ("What do I do?"). |
| **Brag Document** | The person's running log of accomplishments and their impact. |
| **Ladder Assessment** | The automated spreadsheet: self vs leader score per pillar, evidence, readiness. |

## 🌱 Growth vocabulary

| Term | Meaning |
|---|---|
| **SBI** | Feedback format: Situation, Behavior, Impact — plus a Status line (new / improving / unchanged / resolved). |
| **Three moves** | Up to three behaviors to change next period, each with a rule that has a number in it. |
| **Arena** | The real upcoming work where the three moves will be practiced and become visible. |
| **At what cost** | The hidden price of a delivery, named in the review (rework, review load, late decisions). |
| **Main message** | The review's closing paragraph: strengths first, verdict, gap, three moves, arena. |
| **Readiness** | Share of pillars the leader scored "Operating at next level" — a conversation prompt, not a decision. |

## 🪜 Career ladder

| Term | Meaning |
|---|---|
| **Career ladder** | Levels × pillars with expectations. Optional; company or generic. |
| **Pillar** | One dimension of a career ladder. Names differ by company and are filled in after the documents are generated. |
| **Generic ladder** | A sample of the levels × pillars shape. It is not a company's ladder; replace it after the documents are generated. |

## 🔌 Delivery

| Term | Meaning |
|---|---|
| **Connector / MCP** | A Google or Microsoft tool the agent can use to create documents directly. |
| **Files fallback** | Creating real `.docx` / `.xlsx` files locally when no Drive / OneDrive tool can write. |
| **Manual fallback** | Filled-in Markdown documents + a HOW-TO-PASTE guide, when there's no connector, filesystem or Python. |
| **Manual Kit** | Release zip with Markdown, Word and spreadsheet templates for use without AI. |

## 🛠️ Software engineering

| Term | Meaning |
|---|---|
| **ADR (Architecture Decision Record)** | A short document that records one technical decision: its context, the alternatives considered, the decision and its consequences. |
| **Supersede** | Replace an older ADR with a new one; the old one stays, marked "Superseded by". |
| **Service handoff** | Transferring ownership of a service to another team (or a fresh agent session), with the context and checklists they need. |
| **Incoming / outgoing owner** | The team receiving a service / the team handing it over. |

## 🔧 Technical terms

| Term | Meaning |
|---|---|
| **AI assistant / agent** | The AI tool you talk to, such as Claude or Cursor, that can use skills. |
| **Skill** | A packaged set of instructions (and sometimes templates and scripts) that teaches the assistant one practice. |
| **MCP server** | The technical name for a connector in Claude Code and Cursor: a plug-in that lets the assistant work inside another app. |
| **CI (continuous integration)** | A robot that automatically runs a list of checks on every proposed change and blocks it if anything fails. |
| **Pull request (PR)** | A proposed change to the repository, reviewed and checked before it's accepted. |
| **Release** | A published version of the repository, with downloadable files such as the Manual Kits. |
